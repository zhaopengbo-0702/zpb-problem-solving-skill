# 行为验收案例

这些案例用于检查 skill 是否真的帮助正确、完整地讲题，而不只是机械生成七个标题。给独立评估者提供 SKILL.md、需要的引用文件和下面的题目；先不要提供预期答案。检查实际输出后再判断是否通过。

## 案例一：数学题的定义域与边界

请求：使用这个 skill，面向零基础完整讲解下面的题，并完成默认七步。

题目：设函数如下，求定义域、单调区间和值域，并解释为什么不能把一个不属于定义域的边界点当作可取值点。

\[
f(x)=\ln x-x.
\]

重点检查：定义域没有遗漏；导数符号与单调性正确；区分最大值与不可达到的边界；首次出现的对数、导数和值域有解释；所有延伸关系有条件。

## 案例二：物理模型与单位换算

请求：使用这个 skill，面向基础薄弱的学生按七步讲透。

题目：一辆车在平直路面行驶，初速度及恒定减速度大小如下。求刹停时间和刹车距离，忽略驾驶员反应时间。

\[
v_0=72\,\mathrm{km/h},\qquad b=5\,\mathrm{m/s^2}.
\]

重点检查：先统一单位；区分加速度的方向与大小；刹停时速度为零；时间与距离单位正确；不把本题模型外的反应距离混入所求；推广到真实车辆时交代模型限制。

## 案例三：算法的边界与多解

请求：使用这个 skill，从零基础讲透，按七步展开，并比较主要方法。

题目：给定一个整数数组和目标整数，判断是否存在两个不同位置的元素，其和等于目标。数组可能含重复值，也可能少于两个元素。解释主要算法、正确性、时间和额外空间开销，可用 Python 演示。

重点检查：不能重复使用同一位置；能处理重复值和短数组；解释暴力法与利用已见数值的方法；说明排序方法需要怎样处理位置；术语和复杂度首次出现时有通俗解释；数学文本与程序代码分别正确排版。

## 案例四：尊重用户缩小范围

请求：沿用案例一，但这次只解释“为什么先检查定义域”，不要求导、不要给最终答案，也不要输出七步全文。

重点检查：确实只解释指定部分；不泄漏后续答案；不因 skill 默认七步而忽略用户当前要求。

## 共同验收要求

- 先看题目答案和证明是否正确，再看教学表达。
- 完整请求覆盖七步及拓展四项，局部请求尊重最新范围。
- 生活类比能对应实际操作；每一小问有可复现推导。
- 变形、备选证明和跨领域应用经核验，模型假设明确。
- 不承诺穷尽所有解法，不捏造评分、命题心理或自身现实身份。
- 不包含原始数表题的专有答案、账号凭据或用户私人上下文。
